# Предсказание растворимости — версия для Way2Drug

Веб-версия модели из проекта `tgnn-solv`. Вход — SMILES органического вещества, выход —
предсказанная растворимость в 27 растворителях при 25 °C, отсортированная от лучшего
растворителя к худшему, с интервалом и оценкой применимости.

Формат входа выбран под конвенцию платформы: одна структура, как в PASS Online. Растворитель
и температуру пользователь указывать не обязан — сервис отвечает по всей панели, потому что
практический вопрос обычно «в каком растворителе лучше», а не «сколько граммов в этом».

**Три документа, и читать их лучше в таком порядке:**

- [ИНТЕГРАЦИЯ.md](ИНТЕГРАЦИЯ.md) — развёртывание на сервере, схемы подключения, ресурсы,
  что выводить на странице, чеклист перед публикацией.
- [MODEL_CARD.md](MODEL_CARD.md) — точность, область применимости и список того, что модель
  **не** предсказывает (полиморфизм, pH, соли, смеси растворителей). До интеграции.
- этот файл — API и формат ответа.

## Установка

```bash
pip install -e .                     # из корня репозитория, ставит tgnn_solv и зависимости
python way2drug/build_assets.py      # один раз: панель растворителей и область применимости
```

Ассеты (`solvent_panel.json`, `train_domain.npz`) собираются из обучающей выборки, а не
хранятся рукописными. Список растворителей поэтому не может разойтись с тем, на чём модель
действительно обучалась.

Нужны: Python ≥3.10, `torch`, `torch_geometric`, `rdkit`, `pandas`, `numpy`.
GPU не требуется — всё считается на CPU.

## Три способа использовать

### 1. Библиотека — рекомендуемый способ интеграции

```python
from w2d_solubility import SolubilityPredictor

predictor = SolubilityPredictor()          # один раз на процесс, не на запрос
result = predictor.predict_panel("CC(=O)Nc1ccc(O)cc1")

result["applicability"]["in_domain"]       # True / False
result["predictions"][0]["solvent_name"]   # лучший растворитель
```

Разделяемого изменяемого состояния у предиктора нет: модели, панель и ассеты только
читаются, а таблица под каждый запрос строится своя. Он рассчитан на то, чтобы жить в
процессе долго: грузится один раз, каждый запрос — 0.19 с на CPU (измерено).

### 2. Командная строка

```bash
python -m w2d_solubility.cli "CC(=O)Nc1ccc(O)cc1"
python -m w2d_solubility.cli --input smiles.txt --json --out result.json
python -m w2d_solubility.cli --temperature 310.15 --top 5 "CC(=O)Oc1ccccc1C(=O)O"
```

Во входном файле одна структура на строку; вторая колонка после пробела, если она есть,
переносится в ответ как `id`. Нераспознанная структура не роняет пакетный прогон — она
возвращается с полем `error`.

### 3. HTTP

```bash
python -m w2d_solubility.service --port 8080
```

```
GET  /health                     состояние и описание модели
GET  /panel                      панель растворителей с опорой в обучающей выборке
GET  /predict?smiles=CCO[&temperature=298.15]
POST /predict                    {"smiles": ["...", "..."], "temperature": 298.15}
```

`service.py` — **не боевой сервер**, а демонстрация формата ответа: `http.server` не
рассчитан на публичную нагрузку. Партия ограничена 50 структурами (каждая структура — это
27 пар, тысяча структур займёт минуты).

## Формат ответа

```json
{
  "canonical_smiles": "CC(=O)Nc1ccc(O)cc1",
  "molar_mass_g_per_mol": 151.165,
  "temperature_K": 298.15,
  "applicability": {
    "nearest_training_similarity": 1.0,
    "molecular_weight": 151.17,
    "heavy_atoms": 11,
    "in_domain": true,
    "notes": ["вещество присутствует в обучающей выборке: это НЕ независимая оценка точности"]
  },
  "predictions": [
    {
      "solvent_name": "DMF",
      "solvent_smiles": "CN(C)C=O",
      "ln_x2": -1.74,
      "ln_x2_sd_ensemble": 0.25,
      "ln_x2_interval": [-3.16, -0.32],
      "mole_fraction": 0.1756,
      "concentration_g_per_l": null,
      "concentration_note": "мольная доля 0.176 выше 0.1: разбавленное приближение неприменимо"
    }
  ],
  "model": { "name": "TGNN-Solv / DirectGNN ensemble", "n_members": 3, "seeds": [42, 43, 44] }
}
```

Поле `notes` внутри `applicability` — это то, что имеет смысл показывать пользователю рядом
с числом. Пустой список означает, что ни один сторож не сработал.

## Что стоит вывести в интерфейсе

Порядок важности, если место на странице ограничено:

1. **Ранжированный список растворителей.** Это ответ на вопрос, ради которого приходят.
2. **Флаг применимости и заметки.** Число вне области применимости хуже отсутствия числа.
3. **Интервал**, а не только точечное значение. Он намеренно широк: уже 0.7 ln-единицы он
   быть не может, потому что настолько расходятся сами лабораторные измерения.
4. Концентрация в г/л — удобна, но выдаётся не всегда, и причина всегда в
   `concentration_note`.

Пометку «вещество присутствует в обучающей выборке» желательно показывать заметно: без неё
пользователь примет предсказание за независимую проверку точности модели.
