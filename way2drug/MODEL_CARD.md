# Карточка модели: предсказание растворимости для Way2Drug

**Версия:** 1.0 · **Дата:** 2026-09-10 · **Контакт:** Н. Л. Поломошнов, `nikitapol@fbb.msu.ru`

## Что это

Ансамбль из трёх графовых нейросетей (**DirectGNN**, сиды 42/43/44), предсказывающий
растворимость органического вещества в органическом растворителе при заданной температуре.
Вход — SMILES растворяемого вещества. Выход — предсказание по панели из 27 растворителей,
отсортированное от лучшего к худшему.

Модель — часть проекта `tgnn-solv`, поданного в *J. Chem. Inf. Model.*
(код: `github.com/doctawho42/tgnn-solv`, данные: `10.5281/zenodo.22263434`).

**Чекпойнты:** `checkpoints/e5_current_split/directgnn_seed{42,43,44}.pt`, обучены 2026-06-29.

## Почему именно эта модель, а не «главная» из статьи

Статья построена вокруг физически-информированной модели с фиксированным слоем COSMO-SAC.
Для веб-сервиса выбрана не она, и по трём измеренным причинам.

1. **Она точнее.** На одном и том же расщеплении DirectGNN даёт MAE 1.702 ± 0.033, а
   физическая модель — 1.795 ± 0.071.
2. **Она быстрее и проще.** У физической модели внутри итеративный поиск неподвижной
   точки; на CPU это заметно дороже, а главное — число итераций при обучении (16) и при
   выводе (30) в этом проекте **разные числа**, и рассогласование сдвигает MAE в диапазоне
   до 1.08 ln-единицы. Для публичного сервиса это лишний способ ошибиться молча.
3. **Ей нечего добавить пользователю сервиса.** Ценность физической модели —
   интерпретируемое разложение ошибки, и оно живёт в статье. Пользователю, выбирающему
   растворитель, нужен ранжированный список.

Отмечу прямо: в самой статье DirectGNN — **контрольная** модель, а не заглавная. Здесь она
используется потому, что для этой задачи она лучше, а не потому, что она главный результат.

## Данные обучения

| | |
|---|---|
| источник | BigSolDB 2.0 (`10.5281/zenodo.15094979`, CC-BY-4.0) |
| строк в обучении | 111 724 |
| уникальных веществ | 15 665 |
| растворителей | 221 (в панель сервиса вошли 27 с опорой ≥100 разных веществ) |
| расщепление | по остовам Бемиса–Мурко: молекулы с общим скелетом целиком в одной части |

Расщепление по остовам — намеренно жёсткое. При случайном делении метрики выглядят
существенно лучше, но это была бы иллюзия: в тесте оказывались бы ближайшие родственники
обучающих молекул.

## Точность

Измерено на 5608 размеченных тестовых строках; воспроизведено скриптом
`verify_against_checkpoint.py` из этого каталога — расхождение с числами, записанными в
чекпойнтах, **0.0000**.

| | MAE, ln x₂ | «во сколько раз промахивается» |
|---|---|---|
| **ансамбль из трёх (то, что отдаёт сервис)** | **1.593** | ≈ 4.9× |
| лучшая одиночная модель (сид 43) | 1.674 | ≈ 5.3× |
| худшая одиночная модель (сид 42) | 1.749 | ≈ 5.7× |

Усреднение трёх сидов даёт около 0.08 ln-единицы против лучшей одиночной модели — это
единственная причина, по которой сервис держит в памяти три модели, а не одну.

### Что эта точность значит

Ошибка измеряется в логарифмических единицах мольной доли. MAE 1.59 означает, что типичное
предсказание расходится с истиной примерно **в пять раз**. Это много — и вот необходимый
контекст:

- **Шумовой пол данных.** Одно и то же вещество в одном растворителе у двух разных
  лабораторий расходится в 2–5 раз. Ниже этого не опустится никакая модель.
- **Внешний уровень.** Лучшая опубликованная модель на экстраполяции к новым веществам —
  FastSolv, примерно 0.83–0.95 log₁₀ RMSE. Наша модель ей уступает.
- **Ранжирование важнее числа.** Практический вопрос обычно не «сколько граммов», а «в каком
  из растворителей лучше». Сервис поэтому выдаёт отсортированный список, а не одно число.

## Область применимости

Ответ всегда несёт блок `applicability` с тремя независимыми сторожами.

1. **Похожесть.** Максимальный коэффициент Танимото (Morgan, радиус 2, 2048 бит) к 15 665
   обучающим веществам. Ниже 0.40 — предупреждение.
2. **Размер.** Молярная масса вне 68–587 г/моль или число тяжёлых атомов вне 4–38 (p1–p99
   обучающей выборки) — предупреждение.
3. **Температура.** Вне 273–373 K — предупреждение.

**Почему размер проверяется отдельно от похожести.** Двоичный Morgan-фингерпринт слеп к
длине молекулы: у полимера и его короткого олигомера включены одни и те же биты. Измерено на
этих же ассетах: макроцикл C21 даёт Танимото **1.000 к циклопропану**, ПЭГ-20 — к тримеру
ПЭГ, декапептид глицина — 0.900 к дипептиду. По одной похожести сервис объявил бы полимер
«внутри области применимости».

**Что не ловится и сейчас.** Молекула обычного размера с необычной топологией: тот самый
макроцикл C21 лежит внутри конверта по массе и числу атомов, похожесть для него завышена,
и предсказание выйдет без предупреждения. Это известное ограничение метрики.

Отдельный флаг зажигается, если вещество **есть в обучающей выборке** (похожесть 1.000).
Такое предсказание не является независимой оценкой точности, и пользователь должен это видеть.

## Чего модель не делает

- **Полиморфизм.** Разные кристаллические формы одного вещества различаются по растворимости
  в разы. Модель видит только структуру и не знает, о какой форме идёт речь.
- **Ионизация и pH.** Растворимость кислот и оснований в воде сильно зависит от pH; модель
  предсказывает одно число независимо от него.
- **Соли и сокристаллы.** Не поддерживаются: на вход подаётся одна нейтральная структура.
- **Смеси растворителей.** Только чистые растворители из панели.
- **Полимеры, пептиды, белки.** Отсекаются сторожем размера.

## Единицы и пересчёт в г/л

Модель предсказывает `ln x₂` — натуральный логарифм мольной доли. Пересчёт в г/л делается в
разбавленном приближении

    c [моль/л] ≈ x₂ · (ρ_растворителя / M_растворителя) · 1000

и **не выдаётся** в двух случаях, каждый с объяснением в поле `concentration_note`:

- мольная доля выше 0.1 — приближение неприменимо;
- у растворителя нет плотности при 298 K в депонированной таблице (сегодня это только ДМСО).

Константы не вписаны по памяти: плотности берутся из `BigSolDBv2.1_densities.csv`, молярные
массы считаются RDKit. Растворителя без плотности в панели не выбрасываем — мольную долю для
него модель предсказывает так же, теряется только одна колонка.

## Воспроизводимость

```bash
python way2drug/build_assets.py               # панель и область применимости из train.csv
python way2drug/verify_against_checkpoint.py  # MAE сервиса против записанной в чекпойнтах
python -m pytest way2drug/tests -q            # 14 тестов инвариантов
```

`verify_against_checkpoint.py` — главная из этих проверок. Сервис собирает признаки не копией
обучающего кода, а самим обучающим кодом: конфиг достаётся из чекпойнта, флаги признаков
переносятся в загрузчик пересечением сигнатур. Ошибка в этой сборке дала бы **работающий**
сервис с тихо другими числами, и увидеть её можно только сравнением с записанной метрикой.

## Известные риски эксплуатации

- Ансамбль занимает около 60 МБ в памяти; панель из 27 растворителей считается ≈0.4 с на CPU.
- `service.py` — не боевой сервер, а демонстрация формата ответа. Для продакшена импортируйте
  `SolubilityPredictor` в существующий backend.
- Разброс ансамбля из трёх сидов систематически **меньше** настоящей неопределённости: все три
  модели учились на одних данных. Поэтому интервал в ответе не может быть уже межлабораторного
  разброса (0.7 ln-единицы) — это зашито в код.
